# Naselja Srbije bez AP Kosovo i Metohija — отчёт о сборке `naselja-srbija.json`

Сборка 29.10.2026. Все цифры ниже взяты из `build_stats.json`, который `build.py` пишет при каждом запуске.

## 1. Итог

- **4709 записей = 4709 официальных naselja** (RZS 1201IND01, данные на 2025 год, обновлено 27.01.2026: Republika Srbija 6158 − AP Kosovo i Metohija 1449).
- Число совпадает с официальным в каждом из 4 регионов, в каждом из 25 округов (с Gradom Beogradom) и в каждой из 163 opština / gradskih opština, где есть свои naselja (раздел 6).
- Население по переписи 2022 есть у всех 4709 записей, `null` нет. Сумма 6 647 003 равна итогу RZS по Сербии без Косово.
- Координаты есть у всех 4709 записей, и каждая точка лежит внутри официальной границы своего naselja (раздел 7.6).
- Размер: `naselja-srbija.json` — 744 467 байт, gzip −9 — 120 956 байт.

## 3. Формат записи

```json
{"n":"Borča","c":"Борча","o":"Palilula (Beograd)","ok":"Grad Beograd","r":"Beograd","lat":44.86667,"lon":20.46667,"p":51862,"t":"grad"}
```

- `n` — официальное название латиницей с диакритикой. Это латинский регистр RZS; он же совпадает с транслитерацией кириллического названия (проверено для всех 4709).
- `c` — официальное название кириллицей (RZS).
- `o` — opština / grad / gradska opština латиницей, как в шифарнике RZS.
  - Одноимённые общины различаются уточнением: `Palilula (Beograd)`, `Palilula (Niš)`.
  - В городах с gradskim opštinama (Beograd, Novi Sad, Niš, Požarevac, Užice, Vranje) `o` — это gradska opština: Grocka, Pantelej, Kostolac, Sevojno…
  - У объединённых записей `Beograd` и `Niš` поле `o` = `Beograd` / `Niš`.
- `ok` — upravni okrug латиницей; Белград = `Grad Beograd`.
- `r` — регион (NSTJ 2): `Beograd` | `Vojvodina` | `Šumadija i Zapadna Srbija` | `Južna i Istočna Srbija`.
- `lat`, `lon` — WGS84, 5 знаков после запятой (около 1 м).
- `p` — население по переписи 2022; `0` означает, что в 2022 году жителей нет (24 naselja, раздел 7.4).
- `t` — `grad` / `selo` (правило в разделе 7.5).

**Сортировка:** сначала `p` по убыванию, затем название по сербской азбуке (č, ć после c; dž, đ после d; lj после l; nj после n; š после s; ž в конце), затем `o`.

**Уникальный ключ** — пара (`n`, `o`): в одной общине нет двух naselja с одинаковым названием. Одно `n` не уникально (раздел 8).

## 4. Источники

1. **RZS — Republički zavod za statistiku**, портал открытых данных https://opendata.stat.gov.rs/odata/. REST API: `https://opendata.stat.gov.rs/data/WcfJsonRestService.Service1.svc/dataset/<ID>/<lang>/json` (lang 1 = кириллица, 2 = латиница). Прочитано 29.10.2026.
   - `SIFNAS` — šifarnik naselja: matični broj, название (кир./лат.), община;
   - `SIFOPS` — šifarnik opština i gradova с привязкой к NSTJ-oblasti (= upravni okrug);
   - `NSTJ` — номенклатура статистических территориальных единиц;
   - `3104020201IND01` — Popis 2022: население по возрасту и полу по naseljima, плюс тип naselja (gradsko / ostalo) и статус показателя;
   - `31010101IND01` — население по переписям 1948–2022 по naseljima (контрольная сверка; обновлено 12.02.2024);
   - `1201IND01` — površina i broj naselja: официальное число naselja (последний год 2025, обновлено 27.01.2026).
2. **Wikidata** (CC0), https://query.wikidata.org/ — элементы со свойством P13776 «Serbian settlement ID» (= matični broj RZS): координаты P625, сербская подпись, P131 → P3727. Прочитано 29.10.2026.
3. **OpenStreetMap** (© OpenStreetMap contributors, ODbL 1.0), Overpass API https://overpass-api.de/api/interpreter — точки населённых пунктов и границы naselja (`admin_level=9`, `ref:RS:naselje` = код RZS, `population:census:2022`; границы импортированы из данных RGZ — Republički geodetski zavod). Прочитано 29.10.2026.

## 5. Запросы

**RZS:** `SIFNAS/1`, `SIFNAS/2`, `SIFOPS/1`, `SIFOPS/2`, `NSTJ/2`, `3104020201IND01/2`, `31010101IND01/2`, `1201IND01/2`. Фильтры:
- перепись — `IDStarGrupa = '0'`, `IDPol = 0` (все возрасты, оба пола);
- 1201 — последний год (2025), `IDVrPod = 2` (число naselja);
- ряд 1948–2022 — год 2022.

Коды `9xxxxx` (Косово и Метохия) отбрасываются при чтении.

**Wikidata (SPARQL):**
```sparql
SELECT ?item ?id ?coord WHERE { ?item wdt:P13776 ?id . OPTIONAL { ?item wdt:P625 ?coord } }
SELECT ?item ?id ?srl WHERE { ?item wdt:P13776 ?id . ?item rdfs:label ?srl FILTER(LANG(?srl) = "sr") }
SELECT ?item ?id ?mid WHERE { ?item wdt:P13776 ?id . ?item wdt:P131 ?m . ?m wdt:P3727 ?mid }
SELECT ?item ?name ?coord WHERE { VALUES ?name { "Београд"@sr "Ниш"@sr "Нови Сад"@sr }
  ?art schema:about ?item ; schema:isPartOf <https://sr.wikipedia.org/> ; schema:name ?name . ?item wdt:P625 ?coord }
```

**Overpass:**
```
[out:json][timeout:180];area["ISO3166-1"="RS"]["admin_level"="2"]->.a;
node["place"~"^(city|town|village|hamlet|suburb|isolated_dwelling|locality|neighbourhood|quarter)$"](area.a);out body qt;
[out:json][timeout:180];rel["ref:RS:naselje"];out tags bb;
[out:csv(c,r;false;"|")][timeout:180];is_in(<lat>,<lon>);make m c="<код>",r=set(t["ref:RS:naselje"]);out;     (по 80 точек в запросе)
[out:json][timeout:180];rel["ref:RS:naselje"~"^(<код>|<код>|…)$"];out geom;                                     (по 40 границ, только для 291 naselja)
```

## 7. Расхождения и как они решены

### 7.1 Белград и Ниш

RZS делит городское naselje между gradskim opštinama:
- Beograd — 10 статистических частей (коды 791016–791113: Voždovac, Vračar, Zvezdara, Zemun, Novi Beograd, Palilula, Rakovica, Savski venac, Stari grad, Čukarica);

Официальное число naselja считает каждый город один раз, поэтому части объединены в одну запись:
- `Beograd`: p = 1 197 714;
- `Niš`: p = 178 976.

Координаты взяты у элемента Wikidata города (Q3711, Q129259), `t` = `grad`. Novi Sad у RZS — одно naselje (802824), ничего не объединялось.

Если они не нужны в интерфейсе — фильтр `p > 0`.

### 7.5 `t` — grad / selo

У RZS нет понятия «город» для naselja, есть «gradska naselja» переписи 2022 (тип G). Правило:
1. `grad` — все gradska naselja RZS: 167 после объединения Белграда и Ниша.
2. Плюс 28 центров общин, которые RZS относит к «ostala naselja», но название которых совпадает с названием их общины: Preševo (14 219), Barajevo (8967), Bogatić, Batočina, Mali Iđoš, Koceljeva, Ljubovija, Čajetina, Plandište, Bojnik, Žitorađa, Pećinci, Žagubica, Knić, Varvarin, Trgovište, Sečanj, Vladimirci, Doljevac, Golubac, Rekovac, Gadžin Han, Ražanj, Žabari, Nova Crnja, Merošina, Malo Crniće, Crna Trava.
3. Всё остальное — `selo`. Сюда попадают и крупные пригороды, которые RZS считает «ostala»: Kaluđerica 28 483, Sremčica 19 434, Veternik 18 849, Nova Pazova 16 115, Ugrinovci 11 859, Kać 11 067. Всего 39 «sela» больше 5000 жителей.

Итого `grad` 195, `selo` 4514. Маленькие официальные gradska naselja оставлены `grad` (13 меньше 1000 жителей, например Divčibare 86, Kuršumlijska Banja 57). Если интерфейсу нужен «размер», надёжнее `p`, чем `t`.

### 7.6 Координаты

Основной источник — Wikidata: P625 элемента с кодом RZS. Каждая точка проверена по официальной границе своего naselja (границы RGZ в OSM, тег `ref:RS:naselje`) в два прохода.

**1. Рамка границы (bbox, допуск около 300 м).** Вне рамки своего naselja оказались 213 точек Wikidata (не считая части Белграда). Обычно это координаты одноимённого села в другом месте:
- Dublje (Svilajnac) стояло в Мачве, в 150 км;
- Brezovica (Gornji Milanovac) — в 133 км;
- Brestovo (Novi Pazar) — в 124 км;
- всего 51 точка была дальше 10 км, 7 — дальше 50 км.

Чем заменены:
- точкой OSM этого naselja, если она внутри рамки — 210;
- центром рамки — 3 (Gornja Slatina, Trnava (Užice), Ljubić (Čačak));
- ещё у 4 naselja подошла вторая точка того же элемента Wikidata (Mladenovac (selo), Koželj, Aleksandrovac (Negotin), Čenta).

**2. Сам полигон.**
- 1580 точек лежат в рамке только своего naselja. Naselja покрывают территорию без пропусков, значит такие точки внутри своей границы. Контроль: 280 из них проверены Overpass `is_in`, все 280 внутри.
- Остальные 3129 точек проверены `is_in`. Каждая попала ровно в одно naselje.
- 291 точка (6,2 %) лежала в соседнем naselju: в среднем в 1,3 км, p90 2,3 км, максимум 5,8 км. Среди них города: Bor (точка была в Krivelj, 5,8 км), Nova Varoš (в Tikva), Babušnica, Despotovac, Bojnik, Lučani (varošica), Varvarin, Baljevac, Malo Crniće, Sijarinska Banja.
- Все 291 подтверждены по скачанной геометрии границ. Замена: точка OSM внутри границы — 285, центр рамки, если он внутри границы, — 6. Вторые точки Wikidata и расчётная внутренняя точка не понадобились.

**Итог по координатам.** Все 4709 точек внутри официальной границы своего naselja. Источники:
- Wikidata — 4206 (4200 основных, 4 вторые точки, 2 точки городов);
- точки OSM — 494;
- центр рамки границы RGZ/OSM — 9.

Точки Wikidata и OSM обозначают центр села, а не центр его территории. 9 точек «центр рамки» могут лежать в полях, но внутри границы.

**Сверка Wikidata с OSM для справки:** у 4707 naselja нашлась точка OSM (4692 по тегу wikidata, 15 по названию); медианное расстояние 0,34 км, p95 2,44 км.

**Вариант `no-osm`** — только Wikidata: 213 точек вне рамки стали `null`, 290 точек, не прошедших проверку полигона, оставлены как есть (они в соседнем naselju, в среднем в 1,3 км).

## 8. Повторяющиеся названия (оставлены все)

413 названий встречаются больше одного раза, это 1078 записей. Чаще всего:
- Novo Selo — 16, Slatina — 13, Kamenica — 11, Bare — 8;
- Jablanica, Trnava — по 7;
- Belo Polje, Drenovac, Gradac, Izvor, Lipovac, Čitluk — по 6;
- по 5: Aleksandrovac, Bistrica, Brestovac, Brezovica, Cerova, Grabovac, Gradište, Jelašnica, Leskovac, Lukovo, Orašac, Petrovac, Planinica, Sibnica, Toponica, Vrelo.

В 82 случаях одноимённые naselja лежат даже в одном округе (например, 3 Buštranje в Pčinjskom, 3 Kovači в Raškom, Novo Selo по 2–3 в пяти округах). Поэтому в подсказке нужно показывать `o` (общину), а не только округ. В пределах одной общины повторов нет.

## 9. Что исключено

- **1449 naselja АК Косово и Метохия:** коды RZS `9xxxxx`, области RS231–RS235 (Kosovska, Kosovsko-mitrovačka, Kosovsko-pomoravska, Pećka, Prizrenska = Kosovski, Kosovskomitrovački, Kosovskopomoravski, Pećki, Prizrenski okrug). Они отбрасываются при чтении, а `build.py` дополнительно проверяет, что их нет.
- **Больше ничего не исключено:** naselja без жителей оставлены (`p = 0`), дубликаты оставлены.
- **Не входят по определению:** части городов и кварталы (раздел 7.1) — их нет в официальном списке naselja; для поиска они вынесены в `naselja-sinonimi.json`.

## 10. Как пересобрать

1. Открыть https://opendata.stat.gov.rs/odata/ в браузере, вставить в консоль `build_browser.js` и дождаться `window.NAS`. Таблицы RZS в ZIP разбираются в памяти, на диск ничего не скачивается.
2. Там же вставить `crosscheck_osm_browser.js`. Шаг 1b запускается сразу; затем `runBboxQuery()`, после появления `window.NBB` — `bboxCheck()`; затем шаг 1d по инструкции в конце файла (`finalPoints()`, `ambiguity()`, `runPip`, `fetchGeo`, `round2Geo()`).
3. Перенести `window.NAS.tsv`, `.opsTsv`, `.cntTsv`, `window.XCBIG`, `window.BBCHK`, `window.PIPCHK` в `raw/*.psv` и записать их SHA-256 в `raw/SHA256SUMS.browser`.
4. Запустить `python3 build.py` (при необходимости `--with-id`, `--no-osm`). Скрипт остановится, если хоть один входной файл не совпадёт по хэшу.

При новом выпуске 1201IND01 или новой переписи достаточно повторить шаги 1–4. Правки названий в `build.py` привязаны к кодам; `assert` упадёт, если в регистре что-то изменилось.

Overpass нагружен: 1d шёл около 1,5 часа с 1–2 потоками и экспоненциальной паузой. Это нормально для публичного сервера, ускорять параллелью не стоит.

## 11. Лицензии и подпись

- **RZS:** открытые данные, использование с указанием источника — «Izvor: Republički zavod za statistiku».
- **Wikidata:** CC0, подпись не обязательна.
- **OpenStreetMap:** ODbL 1.0. Из OSM в файл попали только координаты 503 записей (раздел 7.6); границы RGZ в OSM использовались для проверки. Это небольшая выборка, но если публиковать сам JSON, правильно добавить «© OpenStreetMap contributors (ODbL)» рядом с источником RZS. Если это нежелательно — `naselja-srbija.no-osm.json`.

## 12. Рекомендации для автокомплита

- Искать одновременно по `n` и `c`, без учёта диакритики (c = č = ć, s = š, z = ž, dj = đ) и регистра; сортировать подсказки по `p`.
- В подсказке показывать «`n`, `o`»; при повторе названия в разных общинах — и `ok`.
- Подключить синонимы из `naselja-sinonimi.json` (раздел 13).

## 13. Синонимы (`naselja-sinonimi.json`)

Формат — по объекту на строку:

```json
{"s":"Batajnica","c":"Батајница","n":"Beograd","o":"Beograd","k":"deo grada"}
{"s":"Rakovica","c":"Раковица","n":"Beograd","o":"Beograd","k":"gradska opština","trap":true}
```

- `s` / `c` — синоним латиницей и кириллицей (`s` = транслитерация `c`, проверено для всех).
- `n` / `o` — целевое naselje ровно как в `naselja-srbija.json`; скрипт проверяет, что пара (`n`, `o`) там есть.
- `k` — `gradska opština` | `deo grada` | `varijanta`.
- `trap: true` — такое же название носит реальное naselje в другом месте, и все такие naselja меньше 1000 жителей. Интерфейс должен показывать сначала район города, потом село.

**Итого 420 синонимов** (397 разных написаний), 39 736 байт, gzip −9 — 6 987 байт.

**`gradska opština` — 35.**

Каждая ведёт на своё главное городское naselje: Zemun, Vračar, Novi Beograd, Čukarica… → Beograd; Medijana, Pantelej, Crveni Krst, Palilula → Niš; Mladenovac → Mladenovac (varoš); Barajevo, Lazarevac, Sopot, Kostolac, Sevojno, Vranjska Banja… → одноимённое naselje.

**Сомнения:**
- 28 названий без собственной точки приняты по списку — их место внутри naselja геометрией не проверено.
- В Белграде часть «кварталов» — небольшие жилые комплексы (Savograd, Avala grad, Gradić Pejton). Оставлены, потому что они в списке sr.wikipedia.
- Kraljevo и Čačak не покрыты. Kragujevac — только 11 кварталов из категории (Aerodrom, Pivara, Stanovo — как gradske opštine).
- `trap` и порог 1000 жителей — договорённость; интерфейс может сам сравнивать население.

**Пересборка:**
1. Сбор списка кварталов — в браузере, на вкладке https://sr.wikipedia.org/, скриптом `kvartovi_browser.js`: MediaWiki API (`action=parse&prop=wikitext`, `list=categorymembers`, `prop=coordinates`), Overpass `(nwr["place"]["name"](bbox);…);out center tags;` и `rel["ref:RS:naselje"~"^(…)$"];out geom;`.
2. Результат — `raw/kvartovi_wiki.psv` (372 строки, хэш в `raw/SHA256SUMS.browser`).
3. Затем `python3 build.py --with-id && python3 build_sinonimi.py`. Журнал всех решений пишется в `sinonimi_stats.json`.
